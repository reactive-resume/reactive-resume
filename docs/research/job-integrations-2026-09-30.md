# Job discovery, page reading, and application integrations

Research date: September 30, 2026. Sources are official API documentation and provider-owned repositories. API behavior is documented capability, not a measured success rate on Reactive Resume users' URLs. No paid-provider benchmark or pricing comparison was performed.

## Verified capabilities

### Search and supplied-URL reading overlap, but differ

| Provider    | Documented capability                                                                                                                                                                                               | Consequence for job importing                                                                                                                                                                                                                                                                    |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Firecrawl   | Search returns titles, descriptions, and URLs; optional `scrapeOptions` adds full-page Markdown, HTML, links, or screenshots. A separate search-then-scrape flow is supported.                                      | Firecrawl already covers both research and page reading. It need not be the only reader, and a search response alone need not contain the description. [Search documentation](https://docs.firecrawl.dev/features/search)                                                                        |
| Tavily      | Search is distinct from Extract. Extract reads supplied URLs in Markdown or text. Supplying `query` reranks content into a bounded set of short chunks. Per-URL failures can accompany an HTTP 200 response.        | For a job description, omit query-focused chunk extraction and inspect successful and failed results. [Extract API](https://docs.tavily.com/documentation/api-reference/endpoint/extract), [Extract best practices](https://docs.tavily.com/documentation/best-practices/best-practices-extract) |
| Parallel    | Search returns objective-relevant excerpts. Extract reads supplied public URLs, including JavaScript-heavy pages and PDFs; it offers focused excerpts or requested full-page Markdown.                              | Full content must be requested for importing a job. Focused excerpts fit research better. [Search quickstart](https://docs.parallel.ai/search/search-quickstart), [Extract quickstart](https://docs.parallel.ai/extract/extract-quickstart)                                                      |
| Exa         | Search can request content. Contents separately reads supplied URLs with text, highlights, or summaries. Cached content is used unless freshness options call for fetching. Text output can have a character limit. | Explicitly select text and freshness appropriate to a live posting; highlights and summaries are not a complete description. [Contents API](https://exa.ai/docs/reference/get-contents), [Contents retrieval](https://exa.ai/docs/reference/contents-retrieval)                                  |
| Jina Reader | `r.jina.ai` reads a supplied URL. `s.jina.ai` performs search and can fetch the top results' content. Reader supports browser and lightweight fetching.                                                             | Suitable as an independent reader candidate; source completeness still needs evaluation. [Provider-owned Reader documentation](https://github.com/jina-ai/reader)                                                                                                                                |

**Inference:** None of these capability lists establishes the best default for Reactive Resume. Benchmark completion of the actual task: a usable, sufficiently complete job description, acceptable latency, source freshness, language coverage, and cost per successful import. Measure company-research quality separately.

### Structured ATS reads improve known-board coverage

| ATS        | Verified read capability                                                                                                                                                                                                                                                                                               | Verified submission boundary                                                                                                                                                                                                                             |
| ---------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Greenhouse | Job Board GET endpoints require no authentication. Company-board job lists can include full descriptions with `content=true`; individual jobs expose posting-specific questions.                                                                                                                                       | Application POST requires Basic Auth with a Job Board API key. This is separate from public reading. [Job Board API](https://docs.greenhouse.io/job-board.html)                                                                                          |
| Ashby      | Public postings API returns an organization's published jobs with HTML/plain descriptions, locations, workplace type, published timestamp, job URL, application URL, and optional compensation. Missing source fields remain missing. `isListed=false` denotes a posting intended to be available only by direct link. | `applicationForm.submit` requires `candidatesWrite` permission. [Public postings API](https://developers.ashbyhq.com/docs/public-job-posting-api), [Application submission API](https://developers.ashbyhq.com/reference/applicationformsubmit)          |
| Lever      | Public postings are scoped by company site. Responses include plain/HTML description fields, additional sections, categories, hosted URL, and application URL. It does not offer full-text search across all open jobs or expose custom application questions.                                                         | Submission POST requires an API key generated by the employer account's Super Admin. Lever recommends its hosted form for handling custom forms, availability, queues, and retries. [Provider-owned Postings API](https://github.com/lever/postings-api) |

**Inference:** These APIs can resolve a supported job link reliably and can power a followed-company jobs list. They are not a global job index. Broad discovery needs separately evaluated search coverage or a licensed job feed; presenting general web search as a complete jobs database would overstate coverage. Do not list unlisted postings discovered through a board feed in broad discovery.

**Inference:** Public ATS reading does not authorize universal candidate submission or provide employer credentials. Start with an employer-hosted application link and an explicit user-confirmed application record. Only add direct submission where an authorized integration provides the necessary access and reliable confirmation.

### A jobs database is a separate integration

Adzuna's search endpoint queries its job-ad database through country-scoped routes. Its examples support role keywords, location, salary minimum, full-time/permanent filters, and sorting. Returned fields include employer, title, location, salary, date, and a redirect URL. The documentation explicitly says the description is a snippet. [Search ads API](https://developer.adzuna.com/docs/search), [API overview](https://developer.adzuna.com/overview)

Adzuna's API terms require listing attribution, give it discretion over access, and place conditions on commercial/research uses. They also restrict contacting third-party content providers. Integration evaluation must cover these terms as well as API fields. [API terms](https://developer.adzuna.com/docs/terms_of_service)

**Inference:** A dedicated job-search backend can support useful applicant filters that generic web results do not reliably carry. A discovery snippet is insufficient for tailoring; obtain complete content through a permitted path or the applicant. Adzuna is an example to evaluate by target country and access terms, not a verified universal recommendation; its redirect URL should not be represented as a confirmed direct employer application URL.

## Recommended product direction

These recommendations are product judgments derived from the capabilities above, not provider promises:

Scope: extend the existing job-import and application-management flow. The repository audit already identified direct HTML/JSON-LD reading with pasted-text recovery, Firecrawl rendering, saved/applied stages, and submitted-document snapshots; these recommendations should preserve and connect those foundations rather than introduce a parallel product.

1. Make “Save a job” the core action. Accept a link or pasted text without forcing the applicant to understand scraping services. Resolve recognized ATS URLs through their documented public APIs; use the configured reader for other public URLs; preserve pasted-text recovery.
2. Save an immutable source snapshot with canonical job URL, application URL, retrieval time, and extraction method. Distinguish source facts from inferred fields and missing fields. Let users correct the draft before creating application documents.
3. Treat research, page reading, and job discovery as three capabilities. Credentials can be one connection offering several capabilities. General settings need not expose several vendor selectors during the applicant's first job import; advanced settings can select defaults and test a connection.
4. Keep the applicant's resume out of web search and reading requests. Public URLs and narrow company queries are enough; combine retrieved content with applicant evidence inside the existing authorized AI workflow.
5. Make tailoring reviewable. Show requirements beside resume evidence, identify gaps, and propose edits with a diff. Do not convert unknown experience or qualifications into confident claims. Preserve the base resume and bind the final submitted document version to the application record.
6. “Prepare application” can create the resume, cover letter, and reusable answers. “Open employer application” hands off to the canonical form. Only mark submitted after user confirmation or a trustworthy submission receipt; opening a URL is not an application.
7. Build provider openness incrementally: retain Firecrawl, add one complementary reader after a small benchmark, then expose community adapters with a documented contract. A custom endpoint should be a deployment-owner feature with the existing network protections, not arbitrary tenant access to internal services.

## Small benchmark before choosing a default

Use a fixed, public corpus covering Greenhouse, Ashby, Lever, custom career sites, JavaScript-heavy postings, non-English descriptions, closed jobs, redirects, and inaccessible pages. Record description completeness, preserved requirements and compensation, wrong-page detection, freshness, latency, failure recovery, and cost per usable import. Record provider modes and output limits so a summary is not compared with full text. Never use private resumes in this corpus.

For discovery, evaluate location and remote eligibility, relevant role coverage, stale listings, duplicate resolution, and direct application URLs. Review actual candidate correction and preparation time. Application count alone rewards low-quality automation.

## Research limitations

No requests were made with paid credentials; no applications were submitted. Pricing, quotas, and vendor performance were not benchmarked. Pricing and vendor marketing performance claims are intentionally excluded. Context7 resolution and current documentation were used for Firecrawl, Tavily, Parallel, Exa, Jina, Greenhouse, and Ashby. Context7 returned no relevant Lever or Adzuna library after two resolutions each; official repository or website documentation supplied their API evidence instead. Deployment-specific reliability, storage terms, quotas, and language success rates need validation before selecting a hosted default.
