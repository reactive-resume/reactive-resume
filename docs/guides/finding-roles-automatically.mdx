title: "Find roles while you are busy"
description: "Set a discovery schedule, review open postings and track only the jobs you choose."
---

You have a job already and little time to scroll job boards. Set up a search once, then review new roles in **Career → Today** when you have time.

Discovery reads new search results to check that they are individual open job postings. It skips results it cannot confirm as postings, including recognized closed roles. A posting can close after that check, so read it before applying. The number of new roles varies; there is no promised daily quota.

**Remind me** uses the same follow-up date and note as the application. A follow-up set in application details appears in Today, and a Today reminder updates the application's Next step. Edit either location to change it. Delete clears both; Undo cancels the pending deletion. Pausing only stops delivery. Add a **Follow-up note** to remember what to ask. An existing reminder stays attached to its application; create a separate follow-up for another application.

## Set what you are looking for

In **Career → Knowledge → Preferences**, record target roles, places, minimum base salary, maximum office days and what matters to you. These help explain matches and unknown details.

**Where you're looking for work** sets the countries web searches target, up to three. It starts with the country of your account timezone, marked **From your timezone**. If your account is still on UTC and you have never set search countries, your first search or enabled discovery schedule saves the country of your device timezone. Select **Add a country** to search for more, or remove every country to search anywhere. **Use my timezone** returns to the automatic country.

Enter salary as a full amount, such as **95000**, rather than **95k**. Invalid shorthand stays visible until corrected. Choose **Any** for maximum office days when you have no requirement; it clears a previous choice.

### Optional role suggestions

**Suggest target roles (optional AI)** in Preferences lets you choose a tested AI connection, a resume to share, and whether to **Share enabled shared Knowledge**. Both context controls start off. Generation sends only the selected resume and up to 20 active shared facts; it does not send private application facts, your application profile, saved answers or other documents. The connection's label, provider and model identify the recipient; its service may charge.

Role-suggestion approval covers the displayed connection, model and address. A request keeps its approved recipient. If saved settings or the key changed before the request starts, it sends nothing and asks you to refresh AI connections, choose the recipient again and approve a new request.

Suggestions show the exact Knowledge statements or resume excerpt they cite. They are AI ideas, not verified qualifications or hiring predictions. Edit **Review target roles, one per line**, then choose **Use reviewed roles in preferences**. This replaces your target roles; wait for **Saved** before opening a new discovery schedule. Merely generating suggestions changes no preferences, search, schedule or evidence. You can always enter roles manually without AI. Corrected or switched-off resume sources cannot be replayed through this action; use enabled Knowledge or another resume instead. The selected connection must still be available when the server authorizes the request: switching it off or deleting it during preparation stops that request. Selected resume and Knowledge versions are checked again in that same short authorization step before sending. Changes while preparing roles require a new request; changes during generation discard the response. Switching off context after transmission cannot recall data already sent to your provider.

Set your timezone in **Settings → Preferences**. New schedules use that timezone. Existing exact-time and repeating schedules retain their saved timezone when edited. Date-only follow-ups from earlier app versions run at 09:00 in your current account timezone; changing it moves pending reminders with that clock. Already delivered follow-ups stay delivered.

Discovery needs a web search connection or server-configured SearXNG search. Check **Settings → AI & developer → Web access**, or ask your installation's administrator if services are configured centrally. AI text coaching is a separate connection. It is not required just to schedule a discovery search.

## Schedule the search

1. Open **Career → Today**.
2. In **Schedules**, select **Add**, then **Find roles**.
3. Edit **Look for**. It starts from your preferences; include roles, places or companies to focus the search.
4. Choose **Every day**, **Every 3 days** or **Every week**.
5. Set **First run** and **Time**. For morning results, choose a morning time such as 08:00.
6. Leave **Turn this schedule on** enabled and select **Save schedule**.

The server runs the schedule while your browser is closed. Only its saved query and search countries go to web search; discovery does not send resumes or Knowledge to that service. Found posting links are read by Reactive Resume and the sites being read, with the configured reader used when needed. The schedule names that reader before you enable it. Both search and reading services may charge for usage. Repeating schedules retain local wall-clock time across clock changes. A nonexistent time moves forward on a recurrence; an invalid initial time must be corrected before saving. Missed occurrences combine into one run, rather than replaying every missed search. See [Schedule controls](/guides/career-workspace-reference#schedules) for delivery and email options.

## Review the roles on Today

When discovery finishes, **Needs you** tells you there are results to review. Under **New roles from your search**, each role has a summary, posting link and match details.

Each card names its posting source and when the link was last seen in search. New discoveries also record the actual search query and posting check time. Earlier results explicitly mark missing provenance as unknown. A check is historical: the job may have changed or closed since then. Publication dates are not retained, and search coverage is incomplete.

**Preference phrase matches** means the posting contains the significant words of a target role or location; **Keyword overlap** shows individual target-role words. Neither is an AI fit assessment, salary/workplace verification or eligibility check. **Salary not detected** and **Workplace arrangement unknown** flag details not established by conservative text checks. Search snippets alone never establish these details. Unknowns are questions to resolve, not confirmation that a preference is met.

For each role:

- **Read posting** to inspect the job before deciding.
- **Track in Applications** to create a Saved application with its posting and match notes. This does not submit an application.
- **Not for me** to dismiss it. Use **Undo** if you change your mind.

Select individual role checkboxes or **Select all roles**, then **Track selected** or **Dismiss selected**. Each action succeeds or fails independently. A partial failure reports counts and keeps available failed roles selected for retry; successful roles leave the queue. Bulk dismiss is immediate; the individual **Not for me** action still offers Undo. Dismissed and already tracked links stay suppressed on later discovery runs. Tracking the same result twice returns the same saved application.

Once tracked, [check Fit](/guides/checking-job-fit) using your experience, then prepare the application.

## Adjust or pause the search

Select a schedule's row to edit its search, frequency or time. Use its switch to pause it without losing those settings. Delete it when you no longer need it; the notice offers **Undo**.

Pausing or changing a schedule cancels its old work still in progress. A cancelled run does not publish a briefing or notification.

Untracked postings found again are rechecked after a week. Changed descriptions or recognized closures update the existing role without another new-role notice.

Changing your preferences updates how role details are matched. Review the schedule's **Look for** text separately when your search direction changes; it was copied from preferences when you created the schedule.

If nothing new appears, check that the schedule is on and when it last ran. A completed search can have no new usable postings. For a failure notice, check the web connection and [troubleshooting](/guides/career-workspace-reference#when-something-does-not-work).
