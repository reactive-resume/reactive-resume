---
title: "Adding an application"
description: "Save a job from a link, pasted posting or optional keyword search, then prepare a resume or record what you already submitted."
---

Save a job as soon as you find one you like, or record an application you've already submitted. Paste the job link or posting text, check the role and company, and save it. A saved posting gives [Check](/guides/checking-your-resume), [the assistant](/guides/using-the-assistant) and [your cover letter](/guides/writing-a-cover-letter) context for this job.

Saving a job and preparing a resume manually work without an AI connection or an external web account.

## Add an application

<Steps>
  <Step title="Open the Save a job dialog">
    In **Applications**, select **Save job**. You can also press <kbd>⌘</kbd> <kbd>K</kbd> (<kbd>Ctrl</kbd> <kbd>K</kbd>{" "}
    on Windows and Linux) and run **Save job**.
  </Step>
  <Step title="Paste the job link or posting">
    Paste into **Job link or posting text**. A single web address counts as a link; anything else counts as posting
    text. Select **Read posting** to retrieve a link's text and any available job details. Reading starts only when you
    select the button; you can also save the link without reading it.
  </Step>
  <Step title="Check the role and company">
    Reading may fill **Role**, **Company**, **Location** and **Salary**. Correct anything that was found, and fill
    missing fields yourself. Only **Role** and **Company** are required.
  </Step>
  <Step title="Pick a stage">
    **Saved** is the default. Choose **Already applied** or **Already interviewing** only if that happened, then confirm
    the application date and select any documents you actually submitted. Your own Saved, Applied and Interview stages
    appear here too. If you applied to the same company before and never heard back, those applications are listed as a
    reminder; you can still save.
  </Step>
  <Step title="Add it">
    Select **Save job** to open its details, or **Record application** when recording a submission. **Save and prepare
    resume** also opens the flow for copying a resume for this job; your original stays unchanged. See [Tailoring a
    resume for a job](/guides/tailoring-a-resume-for-a-job).
  </Step>
</Steps>

## Capture from your browser

In **Save a job**, select **Download browser helper**. Unzip the download, open `chrome://extensions` (or `edge://extensions`), enable **Developer mode**, choose **Load unpacked**, and select the unzipped folder. This helper supports current desktop Chrome and Edge. Other browsers, restricted pages, and embedded frames can use URL or pasted-text import.

Open the helper and **Connect** your installation origin, such as `https://rxresu.me` or `https://resume.example.org`. It stores only that origin. Sign in inside the installation itself; never paste API keys, browser cookies or passwords into the helper. Self-hosted installations need HTTPS; HTTP localhost is allowed for development.

On one posting, open the helper and choose **Capture this posting**. A page's single structured JobPosting supplies role, company, location and description without AI. If unavailable, select only the posting text and capture again. The helper never falls back to sending the whole page. Selected text excludes hidden content and editable notes. Expand any closed job details before selecting their text; a closed disclosure contributes only its visible summary. The helper removes known tracking and session parameters while preserving supported job identifiers. If unknown query parameters could change the job identity or carry credentials, capture stops and asks you to enter the URL or text explicitly. Different jobs with the same title and company are not treated as one structured posting.

Review and correct the URL, **Role**, **Company**, **Location** and **Saved description** in the installation, then choose **Save job**. When already tracked, use **Open tracked job** or **Update posting details**. Updating this way preserves stage, notes and submitted documents. An absent location or description keeps the existing value; use Edit details to clear it intentionally. Capture does not contact the employer, submit an application or mark it applied.

Choose **Disconnect** in the helper to remove its installation setting. Reconnect explicitly to change installations. No posting history or credentials are retained in the helper. Capture opens the review through a URL fragment containing the posting text. The app removes that fragment from its address bar, but the browser may retain it in local or synced browsing history. Use the helper only for text you are comfortable retaining there. Closing or reloading the review before saving discards the capture; sign in first if your sign-in provider needs a full page redirect, then capture again.

## Import a mobile share

In the current native iOS or Android app, connect to your installation using the existing **Another server** sign-in flow. Use the browser's **Share** action and select **Reactive Resume**. Share one URL or the posting text you deliberately selected. On iOS, choose **Keep for review, then reopen app**, return to your Home Screen, and reopen Reactive Resume yourself within 15 minutes. The Share extension finishes normally; it does not launch the app. Open the app and sign in before sharing; after a day without opening it, open it again before sharing. On Android, selecting Reactive Resume opens the review directly. Review the destination installation and imported text; use **Read posting** for a public URL or fill missing fields manually. Save only after correcting the details. Duplicate controls work as above. If the duplicate check is unavailable on an older self-hosted server, saving remains available. Check Applications manually before saving or upgrade the server to enable duplicate detection.

Mobile browsers choose what their share sheet exposes. Many send only a URL, without the page title, description or signed-in page contents. The app receives only the shared payload; it cannot read the browser's session. For a session-only posting, select and share its text, or paste it into **Applications → Save job**. Files and multiple postings are unsupported. A new store build is required for the native receive target; older binaries retain URL/paste import.

Switching server or signing out disconnects the native app through its existing account controls. Captured drafts are account scoped and cleared on identity changes. On iOS, pending raw text stays in the private app group until one-time review, cancellation or account/server change. After 15 minutes it is no longer available for review and is removed on the next app activation. Closing review discards it. A clipped description shows a warning and retains incomplete-source metadata when saved. No capture creates a separate server record: saved posting fields use the existing application, account export and account deletion flows.

## Find a posting with keyword search

If search is available on your installation, the **Save a job** dialog also shows **Search job postings**. Search needs a configured **Web access** connection or server-provided search; an AI provider alone does not enable it. Check **Settings → AI & developer → Web access**, or ask your administrator if the server provides search. You can always paste a link or posting instead.

<Steps>
  <Step title="Search for a role">
    Enter a role, company or location under **Search job postings**, then select **Search**. Search runs only when you
    select the button or press Enter in that field.
  </Step>
  <Step title="Choose a posting">
    Review the result title and description. **View posting** opens the source page in a new tab. Select **Use posting**
    to put its address into **Job link or posting text**. This clears any role, company, location and salary already in
    the dialog; it does not read or save the posting.
  </Step>
  <Step title="Read and review">
    Select **Read posting**, then review **Saved description** and the role, company, location and salary. Correct
    missing or inaccurate details. If the page cannot be read, use **Paste description instead**.
  </Step>
  <Step title="Save the job">
    Choose the appropriate stage, then select **Save job**, **Record application** or **Save and prepare resume**, as
    described above. Search results are not saved as applications until you choose to save.
  </Step>
</Steps>

Search sends your search terms to the configured web search service. Reading a link retrieves its public page through the selected web reader or the built-in reader. **Read posting** reads structured page details without AI. **Read with AI** is optional and names the connection receiving the posting before you choose it. Saving a job never submits an application or contacts the employer.

If search fails or finds nothing useful, change your keywords or paste a posting link directly. For searches that run on a schedule, see [Finding roles automatically](/guides/finding-roles-automatically).

## What gets read from a posting

**Read posting** uses structured page details without AI. The app first confirms that your server supports reading without AI. If that check fails, it sends no parse request: retry, update your server, or enter the details manually. Optional **Read with AI** remains a separate choice and uses your selected [AI connection](/guides/using-ai), disclosed beside the button:

| You paste    | Without an AI provider                                                                | With optional Read with AI                                      |
| ------------ | ------------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| A job link   | Saves the page text; may fill role, company and location from structured job details. | May also fill salary and a short list of what the job asks for. |
| Posting text | Saves the text. Fill in the role and company yourself.                                | May fill role, company, location, salary and requirements.      |

Pasted text is saved up to 20,000 characters. A link keeps its original address; its description stays empty until you read it or paste text. Review **Saved description** after reading. If the description is clipped or incomplete, use **Paste description instead** to replace it before preparing your resume; the original link is retained. Source details such as retrieval time appear when available, and do not guarantee the posting is current.

AI enrichment is optional. If it fails, the retrieved description is retained so you can complete the fields manually. When you pasted the posting text yourself and AI couldn't read it, the text stays in **Job link or posting text** and is saved from there; no second **Saved description** box appears.

<Note>
  Only public HTTP(S) pages can be read. If a page requires sign-in or can't be retrieved, paste its description in
  **Paste description instead**, fill in the role and company, and save. The original link stays with the job.
</Note>

## Add more details

The Add dialog keeps things short on purpose. Once the application is saved, its details sheet opens, where you can add the salary, source, contacts, tags, notes and a follow-up date. To edit everything in one form, including the job posting link, location and linked resume, open the **⋯** menu in the details sheet and select **Edit details…**. See [Managing an application](/guides/managing-an-application).

## Re-read a posting

Reading a different posting replaces values filled by the previous read. Fields you typed or deliberately cleared stay yours, including edits made while the read runs. **Read posting** asks you to approve the named AI destination. With no provider, save the role and company manually; **Set up AI** keeps your input in place. A rejected web key shows **Needs attention** and repair controls. Public links can still use the built-in reader; pasting the posting stays available.
