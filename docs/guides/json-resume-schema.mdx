Every Reactive Resume document is stored as one JSON object, described by a public [JSON Schema](https://json-schema.org). The same schema validates what the API and MCP server accept, what the JSON export produces and what the JSON import reads. Use it to validate files, generate types, get autocompletion in your editor or build integrations that exchange resumes without parsing PDFs.

## Where to get it

The schema is served by every instance at `/schema.json`:

<Info>[https://rxresu.me/schema.json](https://rxresu.me/schema.json)</Info>

It uses the JSON Schema draft 2020-12 dialect and is served as `application/schema+json`. Self-hosted instances serve the schema of the version they run, at their own address. MCP clients can read the same schema as the resource `resume://_meta/schema`.

<Note>
  This is Reactive Resume's own format, not the community [JSON Resume](https://jsonresume.org) format. Reactive Resume can import JSON Resume files; see [Importing resumes](/guides/importing-resumes).
</Note>

## Structure

A resume object has six required top-level properties:

| Property | Contents |
| --- | --- |
| `picture` | The profile photo: its URL, size, shape, rotation, border and shadow, and whether it's hidden. |
| `basics` | Name, headline, email, phone, location, website and custom fields. |
| `summary` | The summary section: its heading settings and its `content` as HTML. |
| `sections` | The built-in sections: `profiles`, `experience`, `education`, `projects`, `skills`, `languages`, `interests`, `awards`, `certifications`, `publications`, `volunteer` and `references`. |
| `customSections` | Sections you added yourself. Each has an `id` and a `type` that picks the item shape it holds. |
| `metadata` | Design and settings: `template`, `layout`, `page`, `design`, `typography`, private `notes`, custom styles (`styleRules`, `stylesheet`) and Check preferences (`check`). |

Each section has display settings and a list of items:

```json
{
  "title": "",
  "icon": "briefcase",
  "columns": 1,
  "hidden": false,
  "showHeading": true,
  "keepTogether": false,
  "startOnNewPage": false,
  "items": [
    {
      "id": "019bef5a-93e4-7746-ad39-44d8cec98ca4",
      "hidden": false,
      "company": "Cascade Studios",
      "position": "Senior Game Developer",
      "location": "Seattle, WA",
      "period": "March 2022 – Present",
      "dates": { "start": "2022-03", "end": null, "present": true },
      "website": { "url": "", "label": "", "inlineLink": false },
      "description": "<p>Lead gameplay programmer on an action-adventure title.</p>",
      "roles": []
    }
  ]
}
```

An empty `title` means the template's default heading in the resume's language.

## Things to know

- **Dates.** Dated items have a `dates` object with `start`, `end` (a year like `"2022"` or a year and month like `"2022-03"`) and `present`. The text in `period` (or `date` for awards, certifications and publications) is still required and still exported, but Reactive Resume rewrites it from `dates` whenever it saves. Write `dates`. See [Using the patch API](/guides/using-the-patch-api#dates).
- **Rich text is HTML.** Fields such as `description` and `summary.content` hold HTML strings.
- **IDs.** Every item and custom section needs a unique `id`. Use a UUID.
- **Cover letters.** The schema still accepts custom sections of type `cover-letter` so older exports stay valid. When you save or import such a resume, Reactive Resume moves each letter into a cover letter of its own and removes the section. See [Writing a cover letter](/guides/writing-a-cover-letter).
- **Templates.** `metadata.template` is one of the 17 templates: `azurill`, `bronzor`, `chikorita`, `ditgar`, `ditto`, `gengar`, `glalie`, `kakuna`, `lapras`, `leafish`, `meowth`, `onyx`, `pikachu`, `porygon`, `rhyhorn`, `scizor` or `smeargle`.
- **No version field.** Resume objects have no top-level `version` or `$schema` property. Don't add one; point your tools at the schema URL instead.

## Validate resume data

Any validator that supports draft 2020-12 works. With [Ajv](https://ajv.js.org) in JavaScript:

```javascript
import Ajv2020 from "ajv/dist/2020.js";

const ajv = new Ajv2020({ strict: false });
const schema = await fetch("https://rxresu.me/schema.json").then((response) => response.json());
const validate = ajv.compile(schema);

if (!validate(resumeData)) console.error(validate.errors);
```

In Python, with [`jsonschema`](https://pypi.org/project/jsonschema/):

```python
import json, urllib.request
from jsonschema import Draft202012Validator

schema = json.load(urllib.request.urlopen("https://rxresu.me/schema.json"))
Draft202012Validator(schema).validate(resume_data)
```

Passing the schema is necessary, not sufficient: the server also checks a few things the schema can't express, such as the size limit on custom styles.

## Get autocompletion in your editor

Associate exported files with the schema. In VS Code, add this to `settings.json`:

```json
{
  "json.schemas": [
    {
      "fileMatch": ["*.resume.json"],
      "url": "https://rxresu.me/schema.json"
    }
  ]
}
```
