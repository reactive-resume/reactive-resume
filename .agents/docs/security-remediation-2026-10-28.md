Replace the patch when upstream publishes a verified fix.

## Product and operational changes

- Every assistant-generated search query and saved career story needs explicit approval of its exact content on web and mobile. Older clients without approval controls cannot complete these pending tools until updated.
- Removing document/posting context excludes earlier history from that reply. An approval from different context choices must be replaced by a new message.
- Passkey enrollment requires a verified mailbox and a sign-in within 24 hours. Password recovery revokes every passkey. Direct HTTP API-key creation also requires recent sign-in. Disabling password authentication now covers usernames.
- Replacing/removing stored application attachments requires delete permission. Write-only integrations can still attach an initial file.
- SMTP must negotiate STARTTLS or use direct TLS. Plaintext-only SMTP configurations fail.
- Oversized/deep/repeated documents, unsafe table spans and oversized fonts are rejected or flattened before expensive work. Existing pathological documents can fail export until simplified. Raw native repeated flow headers need explicit bounded heights; ordinary absolute sidebar backgrounds remain supported.
- Browser recovery copies expire after seven days and are removed on successful sign-out/deletion with other private drafts. Failed sign-out keeps the session and drafts, with an error notice.
- Username reservations now use a database migration. DNS proof expires after seven days of failure even with manual retries; stale domain/provider edits conflict instead of silently replacing newer state.
- Overdue recurring schedules coalesce missed runs and schedule a future occurrence.
- New UI strings were extracted into web/mobile catalogs; untranslated locales use their existing English fallback until translated.

## Release gates and limits

Apply the username-reservation migration through normal deployment. Deploy compatible backend changes and updated web/mobile JavaScript together where possible; update old clients to use new approval controls. Rebuild and verify Forme artifacts from this reviewed source, commit their real manifest/checksum, then produce new signed iOS/Android store binaries. Follow [mobile release handoff](./mobile-release-handoff.md#security-remediation-native-gate-2026-10-28). Never bypass the native source hash.

Not verified here: hosted CI, production migration/deployment, production SMTP/DNS/provider behavior, signed iOS/Android rendering, new native artifact publication/store rollout, or a fresh external security scan. Source/local tests cannot establish that the whole app has no vulnerabilities.
