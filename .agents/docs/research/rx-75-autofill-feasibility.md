Cross-origin experiment serves two task-owned random loopback ports. Both Chromium and host WebKit throw `SecurityError` when app-origin JavaScript attempts to fill the other origin's field; target remains blank. This falsifies a plain web-page/iframe bridge. It does **not** prove a new native extension or embedded browser is impossible. A native bridge choice, implementation, security review, document-upload path and real-device experiment remain necessary. An embedded browser would not automatically cover forms in a user's existing Safari/Chrome tab. Mobile copy/download remains fallback, not equivalent autofill.

Native attempt: T3 `device_list` and `device_open` selected local iPhone 18 Pro / iOS 27.0. The returned bound command's `open com.apple.mobilesafari` failed `DEVICE_IN_USE`. One `--wait 1000` retry also failed. Foreign session was not reused, closed or interrupted. No native UI screenshot, installed-app source match, Hermes, fingerprint, device or store proof is claimed. No installed foreign app/account was opened. Android native integration remains untested. JavaScript-only experiment does not alter native fingerprint; a future native bridge/extension would require new store builds, not merely OTA.

## Reproduce and interpret proof

Use Node 24 and pinned pnpm through repository RTK/mise wrapper. From root:

```sh
rtk proxy mise exec node@24 -- pnpm --filter @reactive-resume/tooling exec node autofill/serve.mjs /tmp/rx75-lab
rtk proxy mise exec node@24 -- pnpm exec node tests/e2e/autofill-prototype.mjs /tmp/rx75-lab
rtk proxy mise exec node@24 -- pnpm --filter @reactive-resume/tooling test autofill/prototype.test.ts capture/content.test.ts capture/popup.test.ts
```

Browser self-check: 12 scenarios = 3 shapes + wrong/missing files + existing value + cross-origin failure, in each of desktop Chromium and host WebKit mobile emulation. Per-field values, manual entries, provenance, PDF names/bytes and zero emitted events/writes are checked. No real employer or account is contacted. PDFs independently parse as one-page PDF 1.4. This does not prove React/ATS event processing or upload acceptance.

Pre-implementation prototype suite failed because module did not exist (0 tests collected). That establishes missing feature, **not** a historical fail-before behavior regression. New owner tests cover 13 cases; existing capture suites add 4. No old autofill implementation exists to reproduce. Real transport negative controls test actual hashing and unavailable files without replacing crypto/File implementations.

Current prerequisite proof: 70 tests across private-profile router, reviewed-answer router and real PostgreSQL career service. Test DB is dedicated labelled `rx75-sol-4627f708-pg`, random published loopback port, synthetic credentials; test migrations/schema cleanup never touch production. This is independent foundation proof, not product/browser integration proof. One pg concurrent-query deprecation warning is retained in log.

Full evidence and final checks live in task delivery directory `/tmp/rx75-delivery/`; frozen delivery README names exact result tree, artifact digests and forward/reverse application proof. Earlier lab build/screenshots are preserved alongside final lab-v2 results. Product production-server UI checks, real-device/native bridge, store build, fingerprint comparison and actual ATS evaluation remain **skipped/blocked**, not passed. Reviewer is dispatched separately by delivery owner; no review result is inherited here.
